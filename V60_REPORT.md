# V60: согласованное разделение бюджетного и договорного потоков

Файл `forecast_2024_v60_consistent_streams.csv` проверен пользователем на лидерборде.
**Public RMSLE за 2024 год: 0.42636.** Точный подтверждённый результат
`forecast_2024_v59_t4.4.csv` — **0.42473**. Таким образом, V60 хуже на 0.00163,
несмотря на улучшение всех шести исторических проверок. V59 остаётся подтверждённым
лучшим вариантом этой пары. Результаты записаны с SHA-256 отправленных файлов
в `output/leaderboard_evaluations.json`.

Целевая величина совпадает с V59: число регистраций заявлений за календарный день
из `registered.csv`, период 20 июня — 31 августа включительно.

## Изменение модели

В V59 источник финансирования присваивался первой строкой `included_ks.csv`
по паре `(abitur_kod, день)`. У одного человека могут быть несколько оснований
финансирования и заявления на разные уровни образования. Результат такого
присвоения зависит от порядка строк; часть строк «Гослиния» также не попадала
в сумму двух моделируемых потоков.

V60 использует явное правило:

1. Соединение по `(abitur_kod, день регистрации, zayav_type_kod)`.
2. Если найдена хотя бы одна строка «Бюджет» или «Гослиния», регистрация относится
   к бюджетному потоку. Остальные, включая отсутствующие в КС, — к договорному.
3. Каждая регистрация попадает ровно в один поток. Повторяющиеся регистрации
   сохраняются, соединение не размножает строки.

Это соглашение для построения признаков и обучающих целей. Оно не определяет
фактическое последующее зачисление или выбор финансирования абитуриентом.
Вся история КС доступна только для обучения на уже завершённых сезонах.

Сохранены ансамбли V59: 5 LightGBM, 3 CatBoost, 2 HistGB на открытых днях
и 3 CatBoost на всех днях; прежние признаки, веса эпох и правило закрытых дней.
Каждый из двух потоков прогнозируется отдельно, затем их количества складываются.
Общий прогноз и потоковый прогноз объединяются в пространстве `log1p`:

```text
z_streams = log1p(expm1(z_budget) + expm1(z_contract))
z_V60 = max(0, -1.2 * z_pool + 2.2 * z_streams)
```

Коэффициент `t=4.4` взят из V59 и не подбирался по этим проверкам.
Закрытые дни получают 0; результат округляется до двух знаков.

## Проверка по времени

Каждый проверяемый сезон прогнозируется только по предыдущим годам. Расписание
закрытых суббот определяется по истории. Нулевые фактические дни проверяемого
сезона не используются как входной график работы.

Официальные исторические календари в исходных данных отсутствуют. Для проверки
заранее зафиксирован общий сценарий дедлайнов: бакалавриат 25 июля, магистратура
29 июля с переносом назад на пятницу при попадании на выходные. Этот сценарий
может отличаться от реальных правил конкретного исторического года. Даты
проверяемого года не восстанавливаются из его фактических количеств.
Исторические дедлайны обучающих лет восстанавливаются только внутри этих лет.
2020 год исключён из перечня оцениваемых сезонов из-за сдвига кампании, но остаётся
в обучении последующих моделей с прежним уменьшенным весом V59.

| Проверяемый год | V59, t=4.4 | V60, t=4.4 | Изменение RMSLE |
|---|---:|---:|---:|
| 2017 | 0.47643 | 0.47397 | −0.00247 |
| 2018 | 0.51550 | 0.50104 | −0.01446 |
| 2019 | 0.46145 | 0.44280 | −0.01866 |
| 2021 | 0.73394 | 0.72013 | −0.01380 |
| 2022 | 0.57537 | 0.56906 | −0.00630 |
| 2023 | 0.74346 | 0.71784 | −0.02561 |
| **Среднее по сезонам** | **0.58436** | **0.57081** | **−0.01355** |

Улучшение наблюдается в 6 из 6 сезонов, средний сезонный RMSLE снизился на 2.32%.
Общий RMSLE по всем 438 дням: 0.59558 → 0.58159. Эти исторические оценки
не являются оценками качества за 2024 год и не сопоставимы напрямую с его 0.424.

Проверялись также разбиение по уровню образования, каналам подачи, дополнительный
рабочий календарь и более длинное обучение CatBoost. Они не дали такого же
устойчивого улучшения относительно V59. Разбиение по каналам оказалось особенно
неустойчивым из-за появления дистанционной подачи в поздние годы. Полные
результаты находятся в `output/v60/ablation_metrics.csv`. Последующая проверка
за 2024 год показала, что улучшение этих исторических сезонов не гарантирует
улучшения на новом сезоне.

## Файл за 2024 год

- 73 последовательные даты, столбцы `date,forecast`.
- Суммарный прогноз: **11 629.26** регистраций.
- 13 нулевых дней: воскресенья и рассчитанные по истории закрытые субботы.
- Все значения конечные и неотрицательные.
- Повтор V59 совпал с `forecast_2024_v59_t4.4.csv` на каждой дате до сотой.
- Рабочий скрипт V60 совпал с исследовательским расчётом на каждой дате до сотой.

## Воспроизведение

Из корня проекта в существующем окружении:

```bash
.venv/bin/python reproducers/v60_consistent_streams.py
.venv/bin/python reproducers/v60_consistent_streams.py --backtest
.venv/bin/python -m unittest discover -s tests -v
```

Зависимости зафиксированы в `requirements-v60.txt`. Скрипт использует существующий
`v59_standalone_4_4.py` и два CSV в `processed_data`. Прежние модели и основной
файл `forecast_2024.csv` не перезаписываются.

Четыре автоматические проверки прошли: соединение сохраняет количество
регистраций и уровни образования; порядок строк КС не меняет распределение;
будущие записи не меняют обучающие потоки; полное удаление факта проверяемого
2023 года из обоих источников сохраняет обучающую таблицу, целевые календарные
признаки и рассчитанное расписание закрытия.

Артефакты:

- `output/v60/backtest_metrics.csv` — метрики по годам.
- `output/v60/backtest_daily.csv` — факт и прогнозы исторических проверок.
- `output/v60/ablation_metrics.csv` — сравнение проверенных архитектур.
- `output/v60/comparison_2024.csv` — изменения прогноза относительно V59.
- `output/v60/components_2024.csv` — три компонента прогноза.
- `output/v60/metadata_2024.json` — параметры, версии библиотек, SHA-256 исходных
  данных и кода; добавлена полученная от пользователя оценка 0.42636. Исходный
  скрипт при новом запуске создаёт метаданные обучения со статусом без оценки;
  журнал измеренных оценок хранится отдельно от этих метаданных.

Следующий вариант — `forecast_2024_v61_orthogonal_funding.csv`; его расчёт и
допущения описаны в `V61_REPORT.md`. Он использует обратную связь лидерборда,
поэтому является калибровкой для этого соревнования.
