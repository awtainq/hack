# Как объяснить и воспроизвести модель

Здесь два разных результата: сохранённый Public **0.39140** относится к V84,
которая использует обратную связь лидерборда. Независимо обучаемая **V85**
имеет доступную проверку на прошлых годах, но её Public score неизвестен.
Описывать их как одну исторически обученную модель с оценкой 0.39140 нельзя.

## V85: задача и данные

Задача — до начала сезона предсказать количество строк регистрации по каждому
дню с 20 июня по 31 августа. Это 73 значения. Количество регистраций и число
уникальных абитуриентов могут отличаться.

`registered.csv` задаёт целевую величину. `included_ks.csv` помогает выделить
вспомогательный бюджетный поток. Соединение выполняется по абитуриенту,
дате и коду типа заявления. Для каждой регистрации выбирается наличие хотя бы
одной бюджетной основы. Остальные строки относятся к прочему потоку, включая
не найденные в справочнике; они не объявляются достоверно договорными.

Регистрации разбиваются двумя способами:

- по образованию: бакалавриат, магистратура, СПО, остальные;
- по сопоставленному финансированию: бюджет и остальные.

Оба разбиения обязаны складываться в исходную дневную сумму. Они не суммируются
друг с другом, поэтому одна регистрация не превращается в две.

## Модель

Один CatBoost совместно предсказывает семь величин в шкале `log(1 + y)`:
общую сумму и шесть вспомогательных потоков. Основной прогноз — общая сумма.
Вспомогательные задачи обучают общие деревья различать формы потоков.

Признаки: день недели, положение в кампании, рабочие дни от начала,
расстояния до ориентиров завершения бакалаврского и магистерского потока.
Исторические разрывы активности оцениваются только по прошлым сезонам.
Для будущего года приняты ориентиры 25 июля и 29 июля с переносом
магистерского ориентира на предыдущий будний день; для 2021 используется
29 июля для бакалавриата. Это упрощённый календарь, не полное расписание всех
программ. Признаков из будущих дневных регистраций нет.

Обычные модельные параметры вынесены в `ModelConfig` и сохранены в
`output/v85/selected_config.json`. Выбор из 12 конфигураций выполняет
`evaluate_v85.py` по среднему RMSLE прошлых сезонов. Это проверка параметров
по доступным историческим меткам; оценки лидерборда в критерии отсутствуют.

Выбранная конфигурация: глубина **3**, **400** итераций, уменьшение веса сезона
вдвое за **3 года**. Сезон 2020 исключён из-за переноса кампании. Воскресенья
обнуляются; субботняя группа обнуляется, если в прошлых сезонах с учётом
веса нулей было больше половины. Это допущение может ошибаться при изменении
режима электронной регистрации. Конкретные даты 2024 в код не записаны.

## Проверенная идея согласования потоков

Из трёх оценок строятся два направления:

```text
d1 = log(1 + сумма потоков по образованию) − прямой лог-прогноз
d2 = log(1 + сумма потоков по финансированию) − прямой лог-прогноз
```

Можно обучить поправку `b1*d1 + b2*d2` регуляризованной линейной регрессией.
Для этого каждому прошлому сезону сначала строится прогноз моделью,
обученной только на ещё более ранних сезонах. Ошибки таких прогнозов известны
и могут служить обучающей выборкой. В отличие от V84, здесь не восстанавливается
ошибка скрытого теста из ответов лидерборда.

В проведённом сравнении вариант **без поправки** оказался лучше по выбранному
критерию. В итоговой конфигурации `ridge_penalty: null`, коэффициенты равны нулю.
Нет оснований оставлять линейную поправку только ради более сложной формулы.

## Проверка качества

Для каждого года модель обучается на более ранних годах. Метрика RMSLE:

```text
sqrt(mean((log(1 + факт) − log(1 + прогноз))²))
```

Выбор конфигурации: 2017, 2018, 2019, 2021, 2022. 2023 показан отдельно,
но уже рассматривался в проекте, поэтому не считается независимым тестом.
Метрика включает все 73 дня, в том числе выходные с нулевыми регистрациями.

| Сезон | RMSLE V85 |
|---|---:|
| 2017 | 0.44268 |
| 2018 | 0.46379 |
| 2019 | 0.51693 |
| 2021 | 0.65559 |
| 2022 | 0.48464 |
| 2023, диагностика | 0.67709 |

Среднее пяти сезонов подбора — **0.51273**. Метрика на всех днях исторического
сезона и Public RMSLE на неизвестном подмножестве 2024 — разные проверки.
Прямой формулы пересчёта между ними нет.

## Запуск

```sh
# Полный повтор подбора на истории и обучение на данных до 2024
.venv/bin/python evaluate_v85.py

# Обучение с уже выбранной конфигурацией
.venv/bin/python v85_historical_model.py train

# Получение прогноза из сохранённых весов
.venv/bin/python v85_historical_model.py predict

# Тесты V84 и V85
.venv/bin/python -m unittest discover -s tests -p 'test_v8[45]*.py' -v
```

Готовый файл V85 — `forecast_2024_v85_historical.csv`.
Веса — `output/v85/model.joblib`. Прогнозы прошлых сезонов и метрики находятся
в `output/v85/`. Основной сабмит и исходная V84 при этих командах не перезаписываются.

## Краткое объяснение для выступления

«Мы прогнозируем дневное количество регистраций. Модель использует календарные
признаки и обучается на завершённых приёмных кампаниях. Общий поток и его
разбиения обучаются совместно. Параметры выбираются последовательной проверкой
на следующих сезонах, а не случайным разделением дней одного года.
Отдельно проверили согласование потоков по прошлым ошибкам; в итоговой версии
оно отключено, поскольку не улучшило выбранный критерий. Для новых сезонов
остаются риски изменения графика и каналов подачи».

К этому объяснению относится **V85 и её историческая проверка**.
Если показывать V84 и Public 0.39140, необходимо отдельно назвать использование
оценок лидерборда и пользовательской нормировки суммы. Подробный аудит:
[V84_REPORT.md](V84_REPORT.md).
