## Протокол проверки

Каждый прогноз прошлого года строится только по более ранним сезонам.
Цель — число строк регистраций по дате; оцениваются **все 73 дня**
с 20 июня по 31 августа, включая нули. RMSLE считается после округления
прогноза до двух десятичных знаков. Старые метрики V66 в таблице ниже взяты из
её отчёта, рассчитанного до округления; разница округления не меняет выводов.

Для V69–V73 конфигурация выбирается по минимальному среднему RMSLE за
2017, 2018, 2019, 2021 и 2022 годы. 2023 не входит в численный критерий
выбора, но уже много раз исследовался, поэтому **это не слепая контрольная
выборка**. Архитектурные решения также могли учитывать ранее замеченные
ошибки. Многочисленный подбор увеличивает риск переобучения на проверках.

Обучающие сезоны сохраняют все даты, включая нулевые. В моделях с календарной
маской воскресенья исключаются из регрессии и получают нулевой прогноз.
Пандемийный 2020 год исключён из новых моделей из-за сдвига кампании.
Исторические фазовые переходы оцениваются только на обучающих годах.
Будущие сроки задаются календарём; они не определяются по фактам целевого года.

## Сравнение

Меньше — лучше. Здесь полные сезоны, а не только рабочие дни.

| Модель | RMSLE 2022 | RMSLE 2023 | Public 2024 |
|---|---:|---:|---:|
| V61 — лучший подтверждённый файл | 0.58168 | 0.74025 | **0.42430** |
| V65 — предыдущая самостоятельная модель | 0.56246 | 0.68453 | 0.53550 |
| V66 — календарный CatBoost | 0.48191 | 0.67961 | неизвестен |
| V68 — прямой CatBoost | 0.55926 | 0.68198 | неизвестен |
| V69 — нормированные профили уровней образования | 0.57530 | 0.72996 | неизвестен |
| V70 — регрессия с календарным ядром | 0.48562 | 0.67583 | неизвестен |
| V71 — совместное обучение четырёх потоков | **0.47292** | 0.68954 | неизвестен |
| V72 — вероятность активности и величина потока | 0.52160 | **0.67362** | неизвестен |
| V73 — совместное обучение уровня образования и финансирования | 0.49255 | 0.70378 | неизвестен |

V61 — ретроспективный перенос конструкции, коэффициенты которой выбирались
с использованием Public 2024. Её прошлые метрики не являются независимой
оценкой выбранных коэффициентов. У V66 также другой критерий выбора:
дополнительный вес последних проверяемых сезонов.

Нельзя переносить разницу этой таблицы непосредственно на лидерборд:
V65 улучшала исторические проверки относительно V61, но проиграла на Public.
Для дальнейшей настройки проверки нужна точная спецификация Public:
какие даты и какой показатель оцениваются.

## Что изменилось в моделях

- **V69:** один CatBoost по четырём уровням образования учит относительный
  профиль, объём оценивается из предшествующих сезонов.
- **V70:** гладкая регрессия по календарному сходству с регуляризацией;
  исторические изменения фаз учитываются при выравнивании сезонов.
- **V71:** один LightGBM учит четыре потока совместно. Основная потеря —
  квадрат ошибки `log(1 + сумма потоков)`, вспомогательная — ошибки потоков.
- **V72:** классификатор активности дня и регрессор положительного потока.
  Прогноз равен `expm1(P(активность) * E[log1p(Y) | активность])`.
  Принудительных нулей нет; веса последних сезонов выбираются по проверкам.
- **V73:** один LightGBM учит 12 потоков: четыре уровня образования ×
  бюджет/договор/неизвестно. Основная потеря относится к общей дневной сумме.
  При одновременном бюджетном и договорном заявлении строка относится к
  бюджету; отсутствие сопоставления не выдаётся за договор. Это условное
  разбиение регистраций, не прогноз фактического зачисления на финансирование.

Все варианты учатся из сырых регистраций; V73 дополнительно читает
`included_ks.csv`. Старые прогнозы и Public score не являются входами обучения.

## Ошибки выходных

В 2023 году на 24 июня пришлось 43 регистрации, все с методом «гос.услуги».
В первой субботе предыдущих сезонов регистраций не было. Нулевой прогноз на
эту дату один даёт вклад `log1p(43)^2 / 73` в среднюю квадратичную лог-ошибку.
Даже при идеальном прогнозе остальных дат RMSLE был бы около **0.443**.
Это свойство конкретной ошибочной календарной маски, не нижняя граница
достижимой точности любой модели.

Для V66 выходные составляют примерно 75% суммы квадратов лог-ошибок
проверки 2023. Изменение электронного приёма важно, но улучшение одной
исторической субботы не доказывает выигрыш в 2024.

## Код и воспроизведение

Зависимости: `requirements-admissions-research.txt`.

```bash
# Полный поиск V73 по прошлым сезонам и обучение итоговой конфигурации.
.venv/bin/python evaluate_coherent_admissions.py

# Обучить только выбранную V73 непосредственно по исходным таблицам.
.venv/bin/python coherent_admissions_model.py train \
  --config output/v73/selected_config.json

# Восстановить прогноз из сохранённых весов, исходные таблицы не нужны.
.venv/bin/python coherent_admissions_model.py predict

# Аналогичный поиск V72.
.venv/bin/python evaluate_activity_admissions.py

# Проверки градиента, границ обучения, разбиения строк и сохранения весов.
.venv/bin/python -m unittest discover -s tests -p test_new_admissions_models.py -v
```

Семь тестов проходят. Численная проверка подтверждает точный градиент
совместной функции потерь. Для деревьев используется положительная
диагональная аппроксимация Гаусса–Ньютона, а не полный гессиан.
Замена всех целевых и последующих наблюдений не меняет прогноз проверки.
Сохранённые модели предсказывают без доступа к исходным таблицам.

Проверены формат, даты, конечность и неотрицательность всех новых CSV.
