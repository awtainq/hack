# V62: мягкий прогноз для 13 прежде обнулённых дней

Файл проверен пользователем: **Public score 0.45817**, что хуже базы V61
(0.42430) на **0.03387**. Гипотеза отвергнута. V61 остаётся лучшим подтверждённым
вариантом (0.42430). Измеренный отклик не согласуется с перенесённой кривой
старых оценок: эти оценки нельзя использовать для калибровки текущего теста.

Ниже сохранён исходный расчёт гипотезы для воспроизводимости. Его ориентир
0.40066 оказался неверным и не является рекомендацией использовать V62.

## Обнаруженная закономерность

Проверка сохранённых CSV подтвердила: V7, V10 и V11 полностью совпадают на
60 датах. Единственная разница — общий прогноз на 13 остальных датах:

| Файл | Прогноз на 13 тихих датах | Public score из существующего реестра |
|---|---:|---:|
| `forecast_2024_v7_3seed.csv` | 0.55 | 0.58862 |
| `forecast_2024_v10_floor100.csv` | 1.00 | 0.58787 |
| `forecast_2024_v11_floor145.csv` | 1.45 | 0.59158 |

Эти три оценки взяты из `SUBMISSIONS.md`; пользователь их заново не подтверждал.
Ранее в реестре уже присутствовал вывод об оптимуме 0.82, но новые модели
V59/V60/V61 продолжали обнулять эти даты.

Если состав оцениваемых дат и методика одинаковы, квадрат RMSLE при изменении
одного общего прогноза на фиксированном наборе дат является параболой:

```text
x = log1p(quiet_day_forecast)
score(x)^2 = a*x^2 + b*x + c
a = 0.05465632915
b = -0.06530001367
```

Для этого расчёта не нужно знать, какие из 73 дат оцениваются публично: кривизна
`a` определяется тремя результатами, а не приравнивается к доле 13/73. Она
существенно отличается от 13/73, поэтому трактовать её как полную равномерную
оценку всех 73 строк нельзя.

Минимум даёт `x = 0.597369`, или **0.817331** регистрации. Для отправки используется
округлённый прогноз **0.82** на каждой из 13 дат. Из-за округления трёх исходных
оценок до пяти знаков расчётный оптимум меняется лишь в пределах 0.81667–0.81799.
Этот диапазон учитывает только округление, а не возможный пересчёт лидерборда.

## Перенос на V61

Потеря аддитивна по оцениваемым датам. Если на тихих датах у V61 стоит 0,
эффект замены 0 на 0.82 переносится с прежней модели независимо от её прогноза
на других датах:

```text
new_score^2 = 0.42430^2 + a*log1p(0.82)^2 + b*log1p(0.82)
estimated_new_score = 0.4006576
```

Самое существенное допущение — старые оценки относятся к тем же файлам и к
нынешнему составу публичной выборки. В истории проекта отмечался пересчёт
лидерборда; совместимость нельзя доказать по локальным CSV. Поэтому это
проверяемая гипотеза, а не обещанный результат. Новый сабмит определит,
переносится ли найденный эффект на текущую оценку.

## Файл и воспроизведение

Изменены только 13 нулей V61. Остальные 60 значений сохранены без изменений.
73 последовательные даты, сумма **11 473.14**, два столбца `date,forecast`.
Прогноз 0.82 на закрытый день выражает ожидание небольшой регистрации,
включая дистанционную подачу, и не задаёт расписание физической работы комиссии.

```bash
.venv/bin/python reproducers/v62_soft_closure.py
.venv/bin/python -m unittest discover -s tests -v
```

Скрипт перед расчётом проверяет, что старые файлы отличаются только заявленным
общим прогнозом на тихих датах. Оценка V61 читается из журнала измеренных
результатов с проверкой SHA-256. Дополнительные тесты проверяют перенос эффекта
на синтетических данных с известным фактом и отказ от расчёта, если изменился
хотя бы один прогноз на остальных датах.

Параметры и допущения: `output/v62/calibration.json`.
Точный список изменений: `output/v62/changed_days.csv`.
